# Bramble Search Benchmark Baseline

Generated by `tests/benchmarks/search-benchmark.php` using the in-memory adapter.

## Methodology

- Seed N documents with shared and unique terms
- Measure average latency over 20 runs for:
  - Filter-only path (`createDbQuery`)
  - Scored path (`searchElements` with `orderBy score`)
- MySQL/Redis production benchmarks should be captured on therapy-organics with `bramble-search/stats --detailed` and representative `/search` queries

## Sample results (in-memory, 1000 documents)

| Path | Approx. latency |
|------|-----------------|
| Filter-only (`createDbQuery`) | ~1.6 ms (1000 docs, in-memory) |
| Scored (`searchElements`) | ~8.3 ms (1000 docs, in-memory) |

Measured speedup: ~5x for filter-only queries at 1000 documents.

Filter-only path is implemented when queries do not require scoring, OR groups, excludes, or attribute scoping. Conditional fuzzy fallback skips when a term already matches more than 50 documents.

## Validated performance changes shipped

1. **PERF-001** — `createDbQuery()` fast path for filter-only element queries
2. **PERF-003** — Skip fuzzy fallback when exact match count exceeds 50 documents per term
